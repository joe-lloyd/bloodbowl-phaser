Suggested module boundaries

Keep the existing planner as the coordinator. Select small capability modules from the actual players and skills on both teams, then compose their proposals and scores. Roster names may supply defaults; current players, conditions, turns, possession and opponent threats determine applicability. 

tactics/
  activationReliability.ts  // gates, support, safe ordering, reroll cost
  vampireFeeding.ts         // reserve Thralls; legal bite endpoints
  vampireDenial.ts          // threaten support and isolate hungry carriers
  gazeAndSpecialAttacks.ts  // target value and follow-up opening
  passingAndThrowing.ts     // passing, punts, throws, catches, jumps
  foulAndWeaponPlans.ts     // ejection risk, victims, weapon lifetime
  kickoffPlans.ts          // use legal event movement rather than skipping

planner → modules selected by capabilities → proposed activations
        → risk and interaction adjustments → legal candidate selection
        → skill-specific pending-decision policy

Extend the engine-derived candidate seam and the planner’s Intent type together. Hard and Legend must search the same expanded actions. Preserve deterministic tie breaking and keep game-rule legality in the engine.
