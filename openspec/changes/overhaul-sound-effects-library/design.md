## Context

`src/ui/sound/` synthesizes every SFX through `@strudel/web`: `catalog.ts` entries build a Strudel `Pattern` (`s("sine*4").n("<c6 d6 e6 d6>")...`), and `SoundManager.playOneShot(pattern, durationMs)` calls `pattern.play()` then `setTimeout(() => cycle.stop(), durationMs)`.

Strudel is a live-coding pattern language: its scheduler (`@strudel/webaudio`'s `Cyclist`/`Scheduler`, wrapped by `@strudel/web`'s module-level REPL) is designed around **one continuously-playing pattern at a time**, the way a DJ/live-coder swaps out "the current loop." `pattern.play()` sets that pattern on the shared global scheduler; it does not allocate an independent, isolated voice the way calling `new Audio()` or starting a `OscillatorNode` does. Every `SoundName` in the catalog (dice roll, catch, pass, block impact, ...) calls `.play()` on this same shared scheduler slot.

`playOneShot`'s `setTimeout`-based stop is a workaround for a scheduler never designed to be one-shot-triggered, and it has a race: if event B fires (`.play()`) before event A's `setTimeout` fires, the scheduler has already moved on to B's pattern by the time A's timeout calls `A_cycle.stop()`. Depending on which pattern is "current" at that moment, that stop either does nothing (A already isn't playing — harmless) or, worse, the scheduler keeps looping whatever pattern is most recently set with no `setTimeout` left able to stop it (its own timeout already fired and stopped a *different*, now-stale cycle reference, or never got scheduled because `isInitialized` raced). Dice roll is the single highest-frequency event in a match (`minRetriggerMs: 150`, fired on essentially every roll, of which there are many per turn) and lowest priority (10) — it is statistically the most likely pattern to be "last one standing" when the race resolves badly, which matches the reported symptom exactly: the dice-roll pattern gets stuck looping forever and other triggers stop producing audible new sound. It also explains why mute "does nothing" once stuck: `SoundSuite.trigger()`'s mute check only gates *new* `.play()` calls; a pattern already looping on Strudel's own scheduler outside `SoundSuite`'s bookkeeping is untouched by it, and even `SoundManager.stop()`'s `hush()` (called only on full page teardown) never runs mid-match.

This is a structural mismatch, not a tunable bug: any fix that keeps calling `.play()` per one-shot trigger on Strudel's single shared scheduler slot is patching the same race, just narrowing the window. The user's notes explicitly float dropping Strudel for "a more js sound effect library."

## Goals / Non-Goals

**Goals:**
- Eliminate the shared-scheduler race structurally: every triggered sound must be an independent unit of playback that cannot be silently replaced or stranded by another trigger.
- Make mute/volume apply to sound that's already playing, not just gate future triggers.
- Redesign the catalog so each of the 13 requested effects is distinct, layered, and matches the requested character (whoosh, crowd cheer, whistle, bone-crunch, dissonant buzz, comedic boing, brighter/louder where asked, punchier where asked).
- Drop the music system and the `uiClick` sound entirely, per the user's explicit ask.
- Fix the debug dashboard's dead "Back to Main Menu" button.
- Keep sound entirely out of the engine/headless import chain (unchanged architectural rule from `sound-effects` spec).

**Non-Goals:**
- Recorded/sampled audio assets (voice-acted crowd, real whistle recordings) — everything stays procedurally synthesized, now via Web Audio primitives instead of Strudel mini-notation. `entry.sampleUrl` (recorded-sample override) stays supported in the catalog shape for any future asset but no entry uses it yet.
- Any change to *which* domain events map to *which* sound category (the `SoundSuite.mount()` binding table stays the same events → same categories, minus `UI_ActionSelected`/`uiClick`).
- Reworking `MatchOptionsMenu`/panel-entry plumbing — mute/volume UI location is unchanged from the prior `overhaul-sound-system` change; only the underlying gain mechanism changes.

## Decisions

**Drop `@strudel/web`/`@strudel/core`; hand-roll a small Web Audio engine.** Considered keeping Strudel and instead giving each one-shot trigger its own isolated sub-scheduler/pattern instance (e.g. via `@strudel/core`'s lower-level `Pattern.queryArc`/manual `webaudioOutput` scheduling instead of the global REPL's `.play()`). Rejected: Strudel's public `@strudel/web` surface doesn't expose a supported "N independent one-shot voices" API — reaching for it means fighting the library's own architecture with unofficial internals, which is more fragile than the bug it's fixing, and still pulls in `@strudel/mini`/`@strudel/transpiler`/`@strudel/tonal` (pattern-language parsing) for something that ultimately just needs a handful of oscillators, a noise buffer, and gain envelopes. Native Web Audio (`AudioContext`, `OscillatorNode`, `AudioBufferSourceNode`, `BiquadFilterNode`, `GainNode`) is a browser-standard API, needs zero dependencies, and each `start()`/`stop()` call operates on its own freshly-created node graph — there is no shared "current pattern" slot to race over, so the stuck-loop bug is structurally impossible, not just less likely. This matches the repo's ruthless-simplification bias: delete the mismatched abstraction rather than patch around it.

**One shared `AudioContext` + one master `GainNode`, created lazily on first user gesture (matching the existing `initAudioOnFirstClick` unlock behavior browsers require).** All per-sound node graphs connect to the master gain, which connects to `ctx.destination`. `soundSettings.subscribe()` updates `masterGain.gain.value` (0 when muted, else `volume`) directly, so a settings change reaches every in-flight sound immediately — no more "mute only affects future triggers." `SoundSuite.trigger()` keeps its own `settings.muted` early-return (skip scheduling entirely when already muted) purely as a minor optimization; the master gain is what makes mute/volume authoritative and instant.

**Each catalog entry becomes a `build(ctx, destination) => { stop(): void }` recipe** composed from a small set of reusable primitives in `SoundManager` (or a new `src/ui/sound/synth.ts`): `tone(freq, {type, attack, decay, gain})` (oscillator + gain envelope), `noiseBurst({filterType, freq, Q, decay, gain})` (a shared pre-generated white-noise `AudioBuffer` run through a `BiquadFilterNode`), `sweep(fromFreq, toFreq, {type, duration, gain})` (oscillator with a linear/exponential `frequency.setValueCurveAtTime`/ramp, used for the pass whoosh and fumble boing), and `stackLayers(...)` (fire several primitives together, e.g. block impact = low thud + noise crack). Every primitive self-schedules its own `stop()`/disconnect via the node's `onended`, so nothing needs a `setTimeout` teardown hack. This keeps the "one line of data per sound" spirit of the old catalog while giving each effect real layering.

**Per-effect character mapping** (addresses "too basic"/"need it to sound like X"):
- `diceRoll`: 4-6 short randomized noise "tick" bursts (tight highpass noise, tiny decay, slight random timing jitter) simulating dice rattling, plus a soft low thud on the last tick for "landing." Randomization (tick count/timing/pitch) replaces the fixed note-pattern approach — still varies per trigger per the existing spec requirement.
- `catch`: bright short tone (`triangle`/`sine`, ~800-1200Hz) with a fast attack and a light highpass noise "snap" layered on top for a satisfying pop.
- `pass`: a bandpass-filtered noise sweep with the filter center frequency ramping across the duration — a whoosh moving through the air.
- `touchdown`: layered lowpass-swept noise (the "roar") plus several randomly-detuned short tones (stand-in "shouts") — a crowd-cheer impression built entirely from noise + oscillators.
- `endOfHalf`: one clean whistle blast — a sine/triangle oscillator around 2.5-3kHz with quick vibrato and a single sustained envelope.
- `sendOff`: the same whistle voice, longer and louder (per the user's "strong whistle... blew the whistle" ask) — distinguishes it from the shorter end-of-half blast.
- `koInjury`: a broadband noise "crack" transient (very short, high gain) immediately followed by a low sine thump with a fast downward pitch envelope — bone-crunch.
- `turnoverWhistle` (kept as the catalog key; content is not a whistle anymore per the user's ask): a sustained dissonant interval — two detuned sawtooth/square oscillators a minor 2nd/tritone apart — "a bad note," not a real whistle.
- `fumble`: a single oscillator with a fast downward exponential frequency ramp (classic comedic "womp"/slide-whistle boing).
- `ballBounce`: raised base frequency and gain versus the old entry — brighter and louder, addressing "too low, can't hear it."
- `knockdown`: stays low-pitched (per the user's explicit "should still be low") but with a fuller layered thud (low sine + a touch of filtered noise) and higher gain for audibility.
- `blockImpact`: thicker layered low thud (two detuned low oscillators) plus a sharper noise crack transient for punch.
- `pushback`/`kickoff`/`foul` keep their existing character (not called out by the user) but are ported onto the same primitives.
- `uiClick` is deleted from `CATALOG`, `SoundName`, `bindingLabels.ts`, and its `UI_ActionSelected` binding in `SoundSuite.mount()`.

**Music removal**: `SoundManager.playOpeningTheme()`/`playGameplayTheme()` are deleted outright (not stubbed) — they're unused in gameplay (only the SoundTest debug page calls `playOpeningTheme`) and the user explicitly wants music dropped. `SoundTest.tsx` loses its "Music Controls" card; the "Stop All" button now just calls the new `SoundManager.stop()` (still useful for silencing SFX while auditioning).

**Debug dashboard "Back to Main Menu" fix**: `SoundTest.tsx` currently does `eventBus.emit(GameEventNames.UI_SceneChange, { scene: "MenuScene" })` — grep confirms no listener anywhere in `src` subscribes to `UI_SceneChange`; it is dead code left over from a pre-router Phaser-scene navigation model, while the app has used `react-router-dom` (`BrowserRouter`/`useNavigate`) for all page navigation for a long time (every other page, including `GameHUD`'s own "Return to Main Menu", calls `navigate("/")`). Fix: `SoundTest` takes the same `useNavigate()` → `navigate("/")` approach; `GameEventNames.UI_SceneChange` and its emit call are removed as dead. (Not touching the general in-match "Return to Main Menu" in `MatchOptionsMenu` — that one already works via `navigate("/")`; the user's complaint traces to the debug dashboard's independent, unrelated button.)

**Teardown**: `SoundManager.stop()` keeps the same call sites (`GamePage.tsx` cleanup) but now: stops/disconnects every currently-active node graph it's tracking (a `Set` of `{stop(): void}` handles, mirroring the pattern `SoundSuite.activeSamples` already used for `<audio>` elements) and optionally suspends the shared `AudioContext`. `SoundSuite.dispose()` keeps unsubscribing event bindings and stopping tracked in-flight units the same way it already tracks `activeSamples` for `sampleUrl` entries — the tracked-set pattern generalizes to "every unit of playback," not just `<audio>` elements.

## Risks / Trade-offs

- [Web Audio requires a user gesture to create/resume the `AudioContext`, same as Strudel did] → keep the existing unlock-on-first-click behavior (`SoundManager.init()` already defers real work; port the same "wait for gesture" pattern using the native `AudioContext.resume()` on a `pointerdown`/`click` listener instead of `@strudel/web`'s `initAudioOnFirstClick`).
- [Hand-rolled synthesis can never sound as rich as a professionally sound-designed/sampled library] → explicitly scoped as "as good as procedural synthesis reasonably gets" in the proposal; a follow-up could swap in recorded samples later via the catalog's existing `sampleUrl` override without touching the engine.
- [Rewriting every catalog entry is a larger diff than a minimal bug patch] → justified because the same rewrite is required either way to satisfy the user's explicit "make each sound better/more layered" ask; doing it once alongside the engine swap avoids a second pass.
- [Removing `@strudel/*` deletes `src/types/strudel.d.ts` and touches `package.json`/lockfile] → mechanical; nothing else in the repo imports `@strudel/*` per grep (confirmed only `src/ui/sound/*` and the `soundTeardown` test reference it), and the `sound-effects` spec's "stays out of the engine import chain" requirement is satisfied more strongly (the whole package is gone, not just kept out of one chain).
- [Existing `soundTeardown.test.ts` mocks `@strudel/web` directly] → rewritten against the new engine's own seams (a fake/stubbed `AudioContext` is a well-trodden pattern for Web Audio unit tests, and jsdom's absence of real audio output is a non-issue since the test only asserts node lifecycle, not sound).
